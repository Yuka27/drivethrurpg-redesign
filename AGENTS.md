## Skill Loading

Use the repository’s installed Intent. If it is unavailable, report the missing dependency instead of downloading a replacement.
Before editing files for a substantial task:

- Run `npm exec --no -- intent list` from the workspace root to see available local skills.
- If a listed skill matches the task, run `npm exec --no -- intent load <package>#<skill>` before changing files.
- Use the loaded `SKILL.md` guidance while making the change.
- Monorepos: when working across packages, run the skill check from the workspace root and prefer the local skill for the package being changed.
- Multiple matches: prefer the most specific local skill for the package or concern you are changing; load additional skills only when the task spans multiple packages or concerns.

## Figma/MCP Design Integration Rules

Use these repository-specific rules when translating a Figma design into this codebase. Treat Figma output as a reference to adapt, not code to copy wholesale. Before using Figma MCP design-to-code tools, load the required `/figma-design-to-code` skill and follow its workflow. Reuse existing project conventions and design-system matches; do not invent a parallel system when one already exists.

### Current Design-System State

- **Tokens:** There is no token file, token package, or token transform pipeline. `src/styles.css` imports Tailwind CSS v4 and contains only a small global reset. The starter page uses Tailwind utility classes directly. Do not describe the current project as having a mature token system.
- **Components:** There is no shared component library or component directory yet. `src/routes/index.tsx` defines the only page component (`Home`) inline. There is no Storybook, component documentation, or test setup in the repository.
- **Framework and build:** The app uses React 19, TypeScript, TanStack React Router with file-based routes, and Vite 8. Tailwind CSS v4 is integrated through `@tailwindcss/vite`. `vite.config.ts` enables the router plugin, React plugin, devtools plugin, and TypeScript path resolution. The README calls this TanStack Start, but the dependencies and entry points currently show a Vite/React Router client app; do not assume Start server features are configured.
- **Assets:** No application image, video, or font assets are present, and there is no `public/` directory, asset optimizer, or CDN configuration. If assets are added, use `public/` for files referenced by stable root-relative URLs, or `src/assets/` for files imported through Vite and processed by the build. Keep large media optimized at source; do not claim a CDN or optimization pipeline exists unless configured.
- **Icons:** No icon package or icon assets are present. There is no established icon naming/import convention. When the design requires icons, use a consistent accessible icon source and keep icon-only controls labeled for assistive technology; avoid introducing a bespoke icon collection without a clear need.
- **Styling and responsiveness:** Styling is Tailwind utility-first, with global CSS in `src/styles.css` imported by `src/routes/__root.tsx`. There are no CSS Modules, CSS-in-JS libraries, component-scoped styles, or existing responsive patterns beyond Tailwind's available utilities. No custom breakpoints or responsive token layer is configured.
- **Organization:** `src/routes/` owns route components; `src/router.tsx` and `src/main.tsx` create and mount the router; `src/routeTree.gen.ts` is generated by TanStack Router and must not be edited manually. The codebase is a small starter, not yet organized into feature modules.

### Token and Styling Rules

1. Check `src/styles.css` and existing route/component classes before introducing design values. There are currently no reusable project tokens, so record that fact rather than implying Figma variables already map to code.
2. For a design-system implementation, define reusable values centrally in `src/styles.css` using Tailwind v4's `@theme` where they should generate Tailwind utilities. Use semantic names and map Figma variables to these shared values instead of scattering raw colors, spacing, or type values across routes.
3. Keep global resets and truly global defaults in `src/styles.css`. Prefer Tailwind utilities for local layout and responsive variants; add another styling method only when there is a concrete need and a consistent pattern to follow.
4. No token transformation tool is installed. Do not add Style Dictionary or another transform pipeline merely to translate a small set of Figma values. Introduce one only if a real multi-target/token-source workflow requires it.

Example of a **proposed convention**, not an existing token definition:

```css
@import 'tailwindcss';

@theme {
  --color-page: #f7f5ef;
  --color-ink: #20231f;
  --color-accent: #a63d2f;
  --font-display: 'Display Face', Georgia, serif;
  --spacing-gutter: 1.5rem;
}
```

### Components, Routes, and Assets

- Keep route registration in file-based route modules under `src/routes/`, following the existing `createFileRoute` pattern. Shared UI should move into a clearly named `src/components/` directory when it is genuinely reused; keep route-specific composition with its route. If the app grows into distinct domains, organize feature-specific components with those features rather than creating a generic abstraction prematurely.
- Use typed React function components and semantic HTML. Extract repeated interface patterns into components instead of duplicating markup or styling. There is no existing component API or Storybook contract to preserve.
- Never hand-edit `src/routeTree.gen.ts`; add or change route files and let the configured TanStack Router plugin regenerate it.
- Import processed assets from `src/assets/` when the asset belongs to a component or page bundle. Put public/static files in `public/` only when stable URLs are needed. Preserve meaningful filenames and alternative text for informative images; decorative images should not gain redundant accessible names.
- There is no current icon library. If a library is introduced, use its named exports consistently and keep icon source names recognizable; do not create arbitrary one-off aliases that obscure the source icon.

Existing route shape:

```tsx
import { createFileRoute } from '@tanstack/react-router'

export const Route = createFileRoute('/')({ component: Home })

function Home() {
  return <main className="p-8">...</main>
}
```

### Figma MCP Handoff

1. Inspect the target Figma node with the Figma design-to-code workflow, including its screenshot/context and available variables or component mappings when relevant. Confirm the target frame, responsive states, and interaction states rather than implementing from a partial screenshot.
2. Map Figma colors, typography, spacing, radii, and effects to existing shared CSS/Tailwind values. If no appropriate token exists, add a reusable token centrally when the value is part of the visual system; keep one-off values local only when they are truly exceptional.
3. Reuse existing React, TanStack Router, and Tailwind conventions. Do not add a second UI framework, CSS methodology, icon system, or token transformer to mirror the design file.
4. Bring over only required assets. Use MCP-exported assets or existing repository assets where suitable; keep asset references local and build-compatible. Do not silently replace meaningful product imagery with generic placeholders.
5. Match the design across required breakpoints and states, then validate layout, keyboard/accessibility behavior, and asset loading in the running app. Do not edit generated route output.

### Commands and Conventions

- `npm run dev` starts Vite on port 3000.
- `npm run build` verifies the production build.
- `npm run lint` runs ESLint; `npm run check` runs Prettier in check mode.
- There is no test script or Storybook script in `package.json` at present.
- Follow the repository's Prettier settings: no semicolons, single-quoted JavaScript/TypeScript strings, and trailing commas. CSS currently uses double quotes in its Tailwind import; follow the formatter and surrounding file style when editing it.
- The repository instructions request the locally installed Intent skill list before substantial changes. Do not download a replacement; report this missing dependency when the prescribed skill workflow is needed.
